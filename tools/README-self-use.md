# 123 目录树与快速搜索

在项目根目录执行（Node.js 内置模块，无额外依赖）：

```powershell
node tools/import-123-tree.js '目录树文件.txt'
node --max-old-space-size=16384 tools/build-fast-search.js
node tools/verify-fast-search.js
node tools/verify-search-interactions.js
```

导入把“我的文件”替换成“自用”，省略中间的“教程”层，将其 10 个分类直接放到“自用”下面；其余层级、空文件夹和原始文件名保留。TXT 只包含名称，不包含真实文件、大小或下载链接。`data/self-use/import-report.json` 记录来源摘要和数量。原有目录及映射保留；重复运行会替换自用的索引映射，不重复增加顶层目录。

自用的子目录打包成 256 份按需读取，避免生成六万个小文件。搜索索引覆盖整个 `data/search-manifest.json`：按规范化后的名称生成连续双字符倒排列表，查询时交集缩小候选，再进行完整关键词匹配。中文、英文、多关键词和类型筛选均受支持。单字符子词使用字符索引。沿用原搜索的名称匹配与旧数据名称替换规则。

`search-worker.js` 在后台读取压缩分片，结果每 1000 条一份，最多同时下载 6 个分片。浏览器使用内置 `DecompressionStream` 解压；内存缓存最多保留 80 个已完成的分片。切换查询或离开搜索会取消旧请求，单次请求 12 秒超时，整个搜索最多 45 秒。快速索引非超时故障会回退原搜索；回退请求同样可取消，并受总时限约束。界面还有独立的 47 秒超时保护。发布时必须包含 `search-worker.js` 和整个 `data/fast-search/`。直接上传已经压缩的 `.json.gz` 文件，不要把这些静态文件配置成自动发送 `Content-Encoding: gzip`，因为客户端执行解压。

目录浏览每页 200 项，分页状态保存在浏览历史中，筛选或进入其他目录时重新从第一页显示。搜索仍每批返回 500 项。只调整交互逻辑时更新 `CLIENT_VERSION` 及首页脚本版本即可，不需要重建数据索引。

修改数据后需要重新生成快速索引，并同步更新导入脚本、`script.js`、`index.html` 中的缓存版本；不要只更新目录而保留旧快速索引。构建需要约数 GB 内存。验证脚本以完整扫描对照快速索引的中文、英文、多词、筛选和无结果查询；输出的 `localMs` 是本机文件读取测试，不代表公网加载时间。
